## useState란?

- **Hook**: 함수형 컴포넌트가 React의 기능(상태 관리, 생명주기 등)을 사용할 수 있게 연결해주는 함수
- **useState**: 함수형 컴포넌트에서 State(상태)를 사용할 수 있게 해주는 Hook

### props vs state

| 구분 | 설명 |
|------|------|
| props | 부모 컴포넌트가 전달, 자식 컴포넌트가 직접 수정하지 않음 |
| state | 컴포넌트 내부에서 관리, 반드시 setter 함수로만 변경 |

### 기본 사용법

```jsx
const { useState } = React; // 구조 분해 할당

function MyComponent() {
    // [ 상태 값, 상태 변경 함수 ] = useState(초기값)
    const [value, setValue] = useState(초기값);
}
```

## 리렌더링 동작 원리

> 상태 변경 함수(setter)를 호출하면 컴포넌트가 **리렌더링**된다. (새로고침 아님)

컴포넌트 함수가 다시 실행되면서, 변경된 state 값을 기준으로 JSX가 다시 만들어진다.

### 예제: MessageManager (버튼으로 메시지/색상 상태 변경)

```jsx
function MessageManager() {
    const [message, setMessage] = useState('초기 상태 메세지입니다.');
    const [textColor, setTextColor] = useState('black');

    console.log('MessageManager 컴포넌트가 렌더링 되었습니다.');

    const handleEnter = () => {
        setMessage('안녕하세요! 환영합니다');
        setTextColor('blue');
    }

    const handleLeave = () => {
        setMessage('안녕히가세요 다음에 또 만나요');
        setTextColor('red');
    }

    return (
        <>
            <h1>함수형 컴포넌트(useState)</h1>
            <h2 style={{ color: textColor }}>{message}</h2>
            <button onClick={handleEnter}>입장</button>
            <button onClick={handleLeave}>퇴장</button>
        </>
    )
}
```

- 버튼 클릭 → `setMessage`, `setTextColor` 호출 → 컴포넌트 리렌더링 → 새 상태로 JSX 재생성
- 콘솔 로그로 실제 리렌더링이 매번 발생하는 것을 확인 가능

## 함수형 업데이트 (Functional Update)

같은 이벤트 핸들러 안에서 **이전 상태를 기준으로 연속 계산**해야 할 때는, setter의 매개변수(prev)를 사용하는 함수형 업데이트 방식을 써야 한다.

### 문제 상황: 의도대로 안 되는 경우

```jsx
onClick={() => {
    setNumber(number + 1);
    setNumber(number + 1);
}}
```

- 두 줄 모두 **현재 렌더링 시점의 같은 `number` 값**을 기준으로 계산됨
- React는 상태 변경을 배치(batch)로 모아서 처리하기 때문에, 의도한 `+2`가 아니라 `+1`로 동작한다

### 해결: 함수형 업데이트

```jsx
const increaseByTwo = () => {
    setNumber((prev) => prev + 1);
    setNumber((prev) => prev + 1);
}
```

- setter에 값 대신 **함수**를 전달하면, React가 "가장 최근 상태"를 인자로 넘겨준다
- 따라서 연속 호출 시에도 각 호출이 직전 결과를 반영하여 누적 계산됨

### 예제: Counter 전체 코드

```jsx
function Counter() {
    const [number, setNumber] = useState(0);

    const increaseByTwo = () => {
        setNumber((prev) => prev + 1);
        setNumber((prev) => prev + 1);
    }

    return (
        <>
            <h1>함수형 컴포넌트 카운터</h1>
            <h2>현재 숫자: {number}</h2>
            <button onClick={() => { setNumber(number + 1) }}>+1</button>
            <button onClick={() => { setNumber(number - 1) }}>-1</button>
            <button onClick={() => {
                setNumber(number + 1);
                setNumber(number + 1);
            }}>+2(의도대로 안됨)</button>
            <button onClick={increaseByTwo}>+2(함수형 업데이트)</button>
        </>
    )
}
```

## 핵심 정리

- state는 setter 함수로만 변경하고, 변경 시 컴포넌트가 리렌더링된다
- 같은 이벤트 안에서 이전 state를 이어서 계산해야 한다면 **함수형 업데이트**(`prev => ...`)를 사용한다
- 값을 직접 넘기는 방식은 배치 처리로 인해 여러 번 호출해도 마지막 값 기준 한 번만 반영될 수 있다

# 제어 컴포넌트(Controlled Component)로 폼 다루기

## 제어 컴포넌트란?

- input의 `value`를 React state와 연결하고, `onChange`로 state를 갱신하는 방식
- input의 실제 표시 값이 항상 state에 의해 "제어"되기 때문에 **제어 컴포넌트**라고 부른다
- 사용자가 입력할 때마다 `onChange` → setter 호출 → 리렌더링 → input value 갱신, 순서로 동작

## 방식 1: input마다 개별 state 관리

```jsx
function SignupFormBasic() {
    const [username, setUsername] = useState('');
    const [email, setEmail] = useState('');

    const handleSignup = () => {
        alert(`아이디: ${username}\n이메일: ${email}\n 회원가입 완료!`);
        setUsername('');
        setEmail('');
    };

    return (
        <>
            <h2>기본적인 이벤트 처리</h2>
            <input
                type="text"
                placeholder="아이디"
                value={username}
                onChange={e => setUsername(e.target.value)}
            />
            <input
                type="email"
                placeholder="이메일"
                value={email}
                onChange={e => setEmail(e.target.value)}
            />
            <button type="button" onClick={handleSignup}>가입하기</button>
        </>
    );
}
```

- input 개수만큼 `useState`와 `onChange` 핸들러가 각각 늘어난다
- input이 몇 개 안 될 때는 직관적이지만, 폼이 커질수록 반복 코드가 늘어난다

## 방식 2: 하나의 객체 state로 여러 input 관리

```jsx
function SignupFormAdvancedI() {
    const [form, setForm] = useState({
        username: '',
        email: ''
    });

    const { username, email } = form;

    const handleChange = (e) => {
        const { name, value } = e.target;
        console.log(name, value);

        setForm({
            ...form,
            [name]: value
        });
    };

    const handleSignup = () => {
        alert(`아이디: ${username}\n이메일: ${email}\n 회원가입 완료!`);
        setForm({ username: '', email: '' });
    };

    return (
        <>
            <h2>효율적인 이벤트 처리</h2>
            <input
                type="text"
                name="username"
                placeholder="아이디"
                value={username}
                onChange={handleChange}
            />
            <input
                type="email"
                name="email"
                placeholder="이메일"
                value={email}
                onChange={handleChange}
            />
            <button type="button" onClick={handleSignup}>가입하기</button>
        </>
    );
}
```

### 핵심 포인트

- input에 `name` 속성을 지정해두고, `handleChange` 하나로 모든 input을 처리
- `e.target`에서 `name`, `value`를 구조 분해로 꺼내 어떤 input이 바뀌었는지 식별
- `setForm({ ...form, [name]: value })`:
  - 스프레드 문법(`...form`)으로 기존 state를 복사
  - `[name]`(computed property name)으로 변경된 필드만 덮어씀
  - state는 직접 수정하지 않고 항상 **새 객체를 만들어 교체**해야 한다 (불변성 유지)

## 방식 1 vs 방식 2 비교

| 구분 | 개별 state | 객체 state |
|------|-----------|-----------|
| state 개수 | input마다 1개 | 폼 전체 1개 |
| onChange 핸들러 | input마다 별도 작성 | 공통 핸들러 하나로 재사용 |
| input 필수 속성 | 없음 | `name` 속성 필수 (state key와 일치해야 함) |
| 적합한 상황 | input이 2~3개로 적을 때 | input이 많거나 폼이 자주 확장될 때 |

## 핵심 정리 (폼 처리)

- 제어 컴포넌트는 `value` + `onChange`로 input과 state를 동기화하는 패턴이다
- input이 많아질수록 객체 state + 공통 `handleChange` 패턴이 코드 중복을 줄여준다
- 객체 state를 갱신할 때는 스프레드 문법으로 불변성을 지키며 새 객체를 만들어야 한다
