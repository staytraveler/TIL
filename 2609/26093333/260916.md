## 1. 비동기(Asynchronous) 프로그래밍

### 동기(Sync) 방식의 문제: 블로킹(Blocking)

동기 처리는 앞선 작업이 끝날 때까지 다음 작업이 무한정 기다리는 방식이다. 웹 페이지에서 시간이 오래 걸리는 작업을 동기 방식으로 처리하면 페이지 전체가 멈춰버린다.

```js
function sleep(delay) {
  const delayUntil = Date.now() + delay;
  while (Date.now() < delayUntil); // 강제로 3초간 코드를 멈춤 (블로킹)
}

document.getElementById('sync-btn').addEventListener('click', () => {
  console.log('동기 작업 시작..');
  sleep(3000); // 3초
  console.log('동기 작업 완료!');
});
```

- 이 3초 동안은 다른 버튼 클릭 등 어떤 반응도 불가능하다 (페이지 전체가 얼어버림).

### 비동기 해결책: 타이머 함수

`setTimeout`, `setInterval`은 대표적인 비동기 함수다. "나중에 할 일"을 브라우저에게 맡겨두고, 자신은 즉시 다음 코드를 실행하여 멈춤 현상을 막는다.

#### setTimeout - 한 번만 예약 실행

```js
// 3초 뒤에 이 함수를 실행해달라고 '예약'만 걸어둔다
const timerId = setTimeout((name) => {
  console.log(`${name}, 3초가 지났습니다.`);
}, 3000, "강사님");

console.log('타이머는 예약되었습니다'); // 이 줄이 먼저 실행됨

clearTimeout(timerId); // 예약된 타이머 취소
```

#### setInterval - 반복 실행 (feat. clearInterval)

```js
let count = 1;
const intervalId = setInterval(() => {
  console.log(`${count}초`);

  if (count++ === 5) {
    clearInterval(intervalId); // 5회 반복 후 정지
    console.log('setInterval 반복이 중지됨');
  }
}, 1000);
```

### 비동기는 어떻게 동작하는가: 이벤트 루프

JavaScript 엔진은 한 번에 한 가지 일만 처리하는 **싱글 스레드**다. 반면 브라우저는 타이머, 네트워크 요청 등을 동시에 처리할 수 있는 **멀티 스레드**다.

| 구성 요소 | 역할 |
|---|---|
| Call Stack | JS 엔진이 지금 실행 중인 작업 공간 |
| Web API | 브라우저가 제공하는 타이머·이벤트·네트워크 처리 공간 |
| Task Queue | 비동기 작업이 끝난 후 대기 중인 콜백들이 서있는 공간 |
| Event Loop | Call Stack이 비었는지 확인하고 Queue의 콜백을 다시 Stack으로 올려주는 관리자 |

```js
console.log('Event Loop 시작!');
setTimeout(() => console.log('Event Loop : 타이머 완료(TaskQueue)'), 2000);
console.log('Event Loop 끝');
// 실행 순서: 시작! → 끝 → (2초 후) 타이머 완료
```

동기 코드(`console.log`)가 먼저 Call Stack에서 모두 처리된 뒤, Web API에서 대기하던 타이머 콜백이 Task Queue를 거쳐 Event Loop에 의해 뒤늦게 실행된다.

## 2. BOM (Browser Object Model)

`window` 객체를 통해 자바스크립트는 HTML 문서(`document`)를 넘어 브라우저 창 자체를 제어할 수 있다. `window`는 전역 객체이므로 생략 가능하다 (`alert()`는 사실 `window.alert()`).

- **DOM**: HTML 문서의 태그·텍스트·속성을 다루는 객체 모델
- **BOM**: 브라우저 창, 주소창, 방문 기록, 화면 정보 등 브라우저 환경 자체를 다루는 객체 모델
- `document`는 `window` 안에 포함된 대표 객체 중 하나

### 사용자와 대화하기: alert, confirm, prompt

```js
// alert: 확인 버튼만 있는 단순 알림창
// confirm: '확인/취소' 질문, boolean 반환
const answer = confirm('결제를 진행하시겠습니까?');
if (answer) {
  message.textContent = '결제를 진행합니다';
} else {
  message.textContent = '결제를 취소했습니다';
}

// prompt: 텍스트 입력받기. 확인 시 입력값, 취소 시 null 반환
const name = prompt('당신의 이름은 무엇인가요');
if (name) {
  message.textContent = `이름 : ${name}`;
} else {
  message.textContent = '이름을 입력하지 않았습니다';
}
```

### 페이지 제어: location 객체 (가장 중요)

```js
location.href = "https://www.google.com";
// URL을 할당하면 해당 페이지로 이동. 방문 기록에 남는다.

location.replace("https://www.naver.com");
// 현재 페이지를 새 페이지로 '대체'. 방문 기록에 남지 않아 뒤로가기 불가.

location.reload();
// 현재 페이지 새로고침. 서버에서 데이터를 다시 받아 초기 상태로 되돌릴 때 사용.
```

### 방문 기록 제어: history 객체

```js
history.back();     // 뒤로 가기
history.forward();  // 앞으로 가기
history.go(-2);     // 2페이지 뒤로 가기
```

브라우저 보안 정책상 방문 기록의 실제 URL 목록은 읽을 수 없다. 이전 방문 페이지를 JS가 전부 알 수 있다면 개인정보 문제가 생기기 때문이다.

### 브라우저/화면 정보 (참고용)

```js
console.log(`브라우저 종류: ${navigator.userAgent}`);
console.log(`전체 화면 너비: ${screen.width}`);
```

주로 통계 수집이나 반응형 처리의 보조 수단으로 사용된다.

## 3. React 시작하기

### React.createElement 방식

```html
<script crossorigin src="https://unpkg.com/react@18/umd/react.development.js"></script>
<script crossorigin src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>
```

```js
// React.createElement('태그명', {속성 객체}, '자식 내용')
// 실제 DOM 노드가 아니라 'React Element' (JS 객체)
const greeting = React.createElement('h1', { className: 'greeting' }, '안녕, 리액트');

const root = ReactDOM.createRoot(document.getElementById('root')); // 시작 지점 지정
root.render(greeting); // 시작 지점에 그려줘(render)
```

기존 방식(`document.createElement` + `appendChild`)과 달리, React는 Element 객체를 만들고 `render`로 그려주는 흐름이다.

### 컴포넌트: 재사용 가능한 UI 부품

컴포넌트는 React 엘리먼트를 반환하는 자바스크립트 함수(또는 클래스)이며, 이름은 반드시 **대문자**로 시작한다.

```js
// 클래스형 컴포넌트 - React.Component를 상속, render() 필수 구현
class TitleClass extends React.Component {
  render() {
    return React.createElement('h1', { className: 'classComponent' },
      "클래스형 컴포넌트입니다."
    );
  }
}

// 함수형 컴포넌트 - createElement 방식 (코드가 길고 복잡함)
function Oldway() {
  return React.createElement(
    'div', null,
    React.createElement('h1', { className: 'greeting' }, "createElement 방식"),
    React.createElement('p', null, '코드가 길고 복잡하다..')
  );
}

// 함수형 컴포넌트 - JSX 방식 (HTML처럼 보여 직관적)
function NewWay() {
  return (
    <div>
      <h1 className='greeting'>JSX 방식</h1>
      <p>HTML처럼 보여서 훨씬 직관적이다</p>
    </div>
  );
}

// 컴포넌트 합성 - 여러 컴포넌트를 조합해서 사용
function App() {
  return (
    // JSX는 여러 태그 반환 시 반드시 하나의 부모 요소로 감싸야 함
    <div>
      <Oldway />
      <NewWay />
    </div>
  );
}
```

### JSX 4가지 규칙

```js
const user = { name: '홍길동', age: 20 };
const customStyle = {
  backgroundColor: 'cornflowerblue',
  color: 'white',
  padding: '10px',
  borderRadius: '5px'
};

function JsxRules() {
  return (
    <>
      {/* 1. {} 안에 자바스크립트 표현식(하나의 값으로 평가되는 코드)을 넣을 수 있다 */}
      <h3>이름 : {user.name}</h3>
      <p>소개: {introduce(user)}</p>

      {/* 2. HTML 속성과 다른 규칙: class -> className, onclick -> onClick */}
      <button className='my-button' onClick={handleClick}>클릭해보세요</button>

      {/* 3. 인라인 스타일은 '객체' 형태로 전달 */}
      <p style={customStyle}>이 문단에는 커스텀 스타일이 적용되었습니다.</p>

      {/* 4. 모든 태그는 반드시 닫혀야 한다 (한 줄짜리도 예외 없음) */}
      한줄짜리 태그도 예외는 없어요. <br /> <hr /> <input />
    </>
  );
}
```

`<>...</>`는 **Fragment**로, JSX에서 여러 요소를 감쌀 때 실제 DOM에 불필요한 태그를 추가하지 않기 위해 쓰는 빈 태그다.

### 실시간 리렌더링: setInterval + render

```js
function Clock() {
  return (
    <>
      <h1>실시간 시계</h1>
      <h2>현재 시간: {new Date().toLocaleTimeString()}</h2>
    </>
  );
}

const root = ReactDOM.createRoot(document.getElementById('root'));

function tick() {
  root.render(<Clock />); // Clock 컴포넌트를 다시 그려줘
}

setInterval(tick, 1000); // 1초마다 tick 실행
```

state 없이도, 매초 `root.render()`를 다시 호출해 화면을 새로 그려주는 방식으로 시계를 구현할 수 있다. (다음 단계에서 배울 `useState`의 필요성을 체감하게 되는 예제)

### Props: 부모 → 자식 데이터 전달

```js
/**
 * props: 부모 컴포넌트가 자식 컴포넌트에게 데이터를 전달하는 '통로'
 * - 읽기 전용 데이터 (자식은 props를 수정할 수 없음)
 * - 데이터는 항상 위에서 아래로 흐른다 (부모 -> 자식)
 * - 함수의 매개변수처럼 생각하면 쉽다
 */
function Greeting({ name = '기본이름', favoriteNumber = 1, children }) {
  return (
    <>
      <h1>안녕하세요, {name}!</h1>
      <h2>제가 좋아하는 숫자는 {favoriteNumber} 입니다.</h2>
      <strong>전달된 자식 요소(children): {children}</strong>
    </>
  );
}

function App() {
  return (
    <>
      {/* 태그 사이에 작성한 내용은 props.children으로 전달된다 */}
      <Greeting name='홍길동' favoriteNumber={5}>props 공부중!</Greeting>
      <Greeting name='유관순' favoriteNumber={8}>
        <div>여러 줄도 가능</div>
        <div>React 최고</div>
      </Greeting>
      <Greeting>
        props를 넘기지 않으면 기본값이 적용됩니다.
      </Greeting>
    </>
  );
}
```

- 변수나 숫자 같은 JS 값을 넘길 때는 `{}` 사용
- 구조분해할당(`{ name = '기본값' }`)으로 기본값 지정 가능
- `children`은 태그 사이에 작성한 내용이 자동으로 전달되는 특수한 prop

## 오늘의 정리

- **비동기**: 블로킹을 피하기 위한 처리 방식이며, Call Stack → Web API → Task Queue → Event Loop 흐름으로 동작한다.
- **BOM**: `window`를 중심으로 브라우저 자체(대화상자, URL, 방문기록, 화면정보)를 제어하는 객체 모델. DOM과는 다루는 대상이 다르다.
- **React 입문**: `createElement` → JSX 순으로 컴포넌트 작성법의 발전 과정을 이해했고, JSX 4대 규칙, 컴포넌트 합성, props를 통한 부모-자식 데이터 전달을 학습했다.
