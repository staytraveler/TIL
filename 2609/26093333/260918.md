## React 이벤트 처리와 상태 관리

### 개별 state vs 객체 state로 폼 관리하기

입력 필드가 여러 개일 때 두 가지 방식으로 관리할 수 있다.

**방식 1: 필드마다 개별 `useState`**

```jsx
function SignupFormBasic() {
    const [username, setUsername] = useState('');
    const [email, setEmail] = useState('');

    const handleSignup = () => {
        alert(`아이디: ${username}\n이메일: ${email}`);
        setUsername('');
        setEmail('');
    };

    return (
        <>
            <input type="text" value={username} onChange={e => setUsername(e.target.value)} />
            <input type="email" value={email} onChange={e => setEmail(e.target.value)} />
            <button onClick={handleSignup}>가입하기</button>
        </>
    );
}
```

**방식 2: 객체 하나로 통합 관리 (효율적)**

`name` 속성을 활용해 하나의 `handleChange`로 모든 필드를 처리할 수 있다.

```jsx
function SignupFormAdvanced() {
    const [form, setForm] = useState({ username: '', email: '' });
    const { username, email } = form;

    const handleChange = (e) => {
        const { name, value } = e.target;
        setForm({ ...form, [name]: value });
    };

    return (
        <>
            <input type="text" name="username" value={username} onChange={handleChange} />
            <input type="email" name="email" value={email} onChange={handleChange} />
        </>
    );
}
```

필드가 많아질수록 방식 2가 코드량이 줄고 유지보수가 쉬워진다.

### 재사용 가능한 컴포넌트 (props.children)

```jsx
function CustomButton(props) {
    return <button onClick={props.onClick}>{props.children}</button>;
}

// 사용
<CustomButton onClick={showWelcomeMessage}><strong>환영 메세지</strong></CustomButton>
```

`props.children`을 활용하면 버튼 안 내용을 자유롭게 커스텀할 수 있는 재사용 컴포넌트를 만들 수 있다. 구조분해 할당(`{ onClick, children }`)으로 받으면 더 깔끔하다.

## 배열 state로 리스트 CRUD 구현하기

### 추가 (Create) — 불변성 유지

```jsx
const handleAdd = () => {
    if (inputValue.trim() === '') return;
    const newName = { id: nextId, text: inputValue };

    // 스프레드 문법으로 새 배열을 만들어 setter에 전달
    // 그래야 React가 '배열이 바뀌었다'는 사실을 안정적으로 인식할 수 있다
    setNames([...names, newName]);
    setNextId(nextId + 1);
    setInputValue('');
};
```

### 삭제 (Delete) — filter로 새 배열 반환

```jsx
const handleRemove = (idToRemove) => {
    // 배열.filter(callback): 콜백이 true를 반환한 요소만 모아 새 배열 반환
    // id로 넘어온 값과 일치하지 않는 객체만 다시 배열로 반환
    const updateNames = names.filter(name => name.id !== idToRemove);
    setNames(updateNames);
};
```

### 렌더링 시 주의점

```jsx
<ul>
    {names.map(name => (
        <li key={name.id} onDoubleClick={() => handleRemove(name.id)}>
            {name.text}
            <button onClick={() => handleRemove(name.id)}>삭제</button>
        </li>
    ))}
</ul>
```

- `map` 렌더링 시 `key`는 index가 아니라 **고유 id**를 써야 한다.
- 이벤트 핸들러에 인자를 넘길 땐 `onClick={() => handleRemove(name.id)}`처럼 **화살표 함수로 감싸서** 전달해야 즉시 실행을 막을 수 있다.

## useEffect 기초

### 렌더링과 부수 효과(side effect)의 분리

`useEffect`는 화면을 그리는 코드가 아니라, **화면이 그려진 뒤 실행할 부수 효과**를 작성하는 자리다.

```jsx
function MessagePrinter() {
    console.log('렌더링');

    useEffect(() => {
        console.log('렌더링 이후 동작...');
    });

    return <h1>{message}</h1>;
}
```

실행 순서: 컴포넌트 본문 실행(`'렌더링'`) → JSX 평가 → 화면 반영 → `useEffect` 콜백 실행.

### 의존성 배열에 따른 3가지 실행 패턴

| 의존성 배열 | 실행 시점 |
|---|---|
| 생략 | 매 렌더링마다 실행 |
| `[]` | 마운트(첫 렌더링) 시 1회만 실행 |
| `[특정값]` | 해당 값이 변경될 때만 실행 |

```jsx
// 1. 의존성 배열 생략: 매 렌더링마다 실행
useEffect(() => {
    console.log('렌더링될 때마다 실행');
});

// 2. 빈 배열: Mount 시에만 실행
useEffect(() => {
    console.log('컴포넌트가 처음 화면에 나타남(Mount)');
}, []);

// 3. 특정 값 지정: 그 값이 바뀔 때만 실행
useEffect(() => {
    console.log(`count값이 ${count}로 변경되어 실행`);
}, [count]);
```

### Cleanup 함수 — 정리 작업

`useEffect`가 함수를 반환하면, 그 함수는 두 시점에 실행된다.

- 컴포넌트가 화면에서 사라지기 직전 (Unmount)
- 의존성이 바뀌어 effect가 재실행되기 직전 — 이전 작업을 정리하고 새 값으로 다시 시작

```jsx
function Timer() {
    useEffect(() => {
        console.log('타이머가 시작되었습니다(Mount)');

        const timerId = setInterval(() => {
            console.log('...1초 경과...');
        }, 1000);

        // cleanup: 생성했던 타이머 제거
        return () => {
            console.log('타이머가 정리되었습니다(Unmount)');
            clearInterval(timerId);
        };
    }, []); // 마운트 시 1회만 실행

    return <h3>타이머 동작 중</h3>;
}
```

`setInterval`처럼 계속 살아있는 리소스는 cleanup 없이 의존성 배열도 빠뜨리면, 리렌더링마다 새 타이머가 계속 쌓이는 버그로 이어진다. `[]` + cleanup 조합이 필수.

### 조건부 마운트/언마운트로 cleanup 직접 확인

```jsx
function App() {
    const [showTimer, setShowTimer] = useState(true);

    return (
        <>
            <button onClick={() => setShowTimer(!showTimer)}>타이머 보이기/숨기기</button>
            {showTimer && <Timer />}
        </>
    );
}
```

버튼으로 `<Timer />`를 껐다 켜보면 언마운트 시 cleanup 함수(`clearInterval` + 로그)가 실제로 실행되는 걸 콘솔에서 확인할 수 있다.
