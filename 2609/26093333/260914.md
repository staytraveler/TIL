## 1. 요소 선택하기

| 메서드 | 반환값 | 특징 |
|---|---|---|
| **⭐ `querySelector(css선택자)`** | 요소 1개 | CSS 선택자 그대로 사용, 가장 범용적 |
| **⭐ `querySelectorAll(css선택자)`** | `NodeList` (고정) | 조건에 맞는 전체 요소, **순회 중 값이 안 바뀌어서 안전** |
| `getElementById(id)` | 요소 1개 | id 전용 |
| `getElementsByClassName(class)` | `HTMLCollection` (실시간) | **DOM 변경이 실시간 반영됨 → 순회 중 요소 삭제/변경 시 length가 같이 줄어들어 버그 발생 주의** |

> ⚠️ **살아있는 목록(`HTMLCollection`) 순회 주의사항**
> `getElementsByClassName` 등으로 얻은 목록을 순회하며 지우면 배열이 실시간으로 줄어들어 일부 요소를 건너뛴다.
> → 스프레드 문법으로 고정 배열로 바꿔서 순회: `const arr = [...$liveList];`

## 2. HTML 가계도(노드) 탐색

| 방향 | 프로퍼티 | 비고 |
|---|---|---|
| 자식 (전체, 텍스트/주석 포함) | `childNodes` | 잘 안 씀 |
| **⭐ 자식 (요소만)** | **`children`** | `HTMLCollection` |
| **⭐ 첫/마지막 자식 요소** | **`firstElementChild` / `lastElementChild`** | |
| **⭐ 부모** | **`parentNode`** (= `parentElement`) | |
| **⭐ 형제 요소** | **`nextElementSibling` / `previousElementSibling`** | |

> 💡 이름에 `Element`가 들어간 프로퍼티를 쓰면 공백/줄바꿈/주석 같은 텍스트 노드를 자동으로 걸러줘서 편하다.

## 3. 텍스트 다루기

| 프로퍼티 | 대상 | 특징 |
|---|---|---|
| `nodeValue` | 텍스트 노드 전용 | 요소 노드에 쓰면 `null` → 자식 텍스트 노드를 직접 찾아가야 해서 번거로움 |
| **⭐ `textContent`** | 요소 노드 | 자손의 모든 텍스트를 가져오고, **할당 시 안전하게 통째로 텍스트로 교체(HTML 파싱 안 함)** → **사용자 입력값 출력 시 기본 선택지** |
| `innerText` | 요소 노드 | 실제 화면에 렌더링된 대로 (CSS 영향 받음), 잘 안 씀 |

## 4. HTML 조작 / 요소 추가

| 방법 | 특징 |
|---|---|
| `innerHTML = '문자열'` | 내부 전체를 HTML로 파싱해서 교체. **사용자 입력을 그대로 넣으면 XSS 취약 → 사용자 입력엔 textContent 사용** |
| `insertAdjacentHTML(위치, html)` | 기존 내용 유지하며 특정 위치에 삽입. 위치 4종: `beforebegin`/`afterbegin`/`beforeend`/`afterend` |
| **⭐ `createElement(태그명)` + `appendChild(자식)`** | 문자열 파싱 없이 요소를 직접 만들어 조립. 가장 안전하고 일반적인 방식 |
| `createDocumentFragment()` | 여러 요소를 한 번에 추가할 때 임시 조립공간으로 사용 → DOM 반영을 한 번만 일으켜서 성능↑ |
| `insertBefore(새 노드, 기준 노드)` | 기준 노드 앞에 삽입 (기준 노드는 반드시 같은 부모의 자식이어야 함) |
| `appendChild(기존 노드)` | 이미 있는 노드를 다른 곳에 넣으면 **복사가 아니라 이동** (원래 자리에서 사라짐) |
| `replaceChild(새 노드, 기존 노드)` | 부모 기준으로 자식 교체 |
| **⭐ `removeChild(자식노드)` / `자식노드.remove()`** | 삭제. `.remove()`가 더 간단해서 자주 씀 |

## 5. CSS 조작: 인라인 스타일 vs 클래스

| 방법 | 언제 쓰나 |
|---|---|
| `element.style.속성 = 값` | 단발성/동적 값 하나만 바꿀 때 (예: 위치, 크기 계산값) |
| **⭐ `element.classList`** | **여러 스타일을 상태 단위로 묶어 관리할 때 (실무 기본값)** |

**classList 메서드**
- **⭐ `.add(클래스명, ...)`** — 추가
- **⭐ `.remove(클래스명, ...)`** — 제거
- **⭐ `.toggle(클래스명)`** — 있으면 제거/없으면 추가, **반환값(boolean)으로 현재 상태 바로 확인 가능** → 버튼 상태 전환 등에 자주 사용
- `.contains(클래스명)` — 존재 여부 확인 (boolean)

> ⚠️ `className = '문자열'`은 기존 클래스 전체를 통째로 덮어써버리므로 주의 (부분 변경엔 classList 사용)

## 6. 어트리뷰트(Attribute) vs 프로퍼티(Property)

| 구분 | 어트리뷰트 | 프로퍼티 |
|---|---|---|
| 의미 | HTML에 적힌 **초기/기본값** | 현재 **DOM 상태(실시간 값)** |
| 예 (input value) | `getAttribute('value')` → 초기값 그대로 유지 | **⭐ `.value`** → 사용자가 입력한 현재 값 |
| 예 (checkbox) | `getAttribute('checked')` → 문자열 | `.checked` → **boolean** |

**어트리뷰트 조작 메서드**
- `getAttribute(이름)` / `setAttribute(이름, 값)` / `hasAttribute(이름)` / `removeAttribute(이름)`

**⭐ data 어트리뷰트 / dataset (실무 자주 사용)**
- HTML: `data-이름="값"` 형태로 커스텀 데이터 저장 (예: `data-board-id="13"`)
- JS: **`element.dataset.이름`** 으로 바로 접근 (camelCase로 변환됨, 예: `data-category-name` → `dataset.categoryName`)
- ⚠️ DOM에서 눈으로 확인 가능 → 비공개/보안용 데이터 저장에는 부적합

## 오늘의 핵심 요약
- 요소 찾을 땐 **`querySelector`/`querySelectorAll`** 기본, 실시간 목록(`getElementsBy...`) 순회는 조심
- 텍스트는 **`textContent`** 우선 (보안 + 간편함)
- 요소 새로 만들 땐 **`createElement` + `appendChild`**, 여러 개면 `DocumentFragment`
- 스타일은 **`classList`**로 상태 단위 관리
- 커스텀 데이터는 **`data-*` + `dataset`**
