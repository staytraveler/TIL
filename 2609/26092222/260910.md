## 1. 배열 기초

배열: 관련된 값들을 하나의 목록으로 묶어 관리하는 자료구조.

```js
const fruits = ['바나나', '복숭아', '키위'];
```

- 인덱스는 **0부터 시작**: `fruits[0] === '바나나'`
- `Array.isArray(fruits)` — 배열인지 확인해서 boolean 반환

## 2. 배열 변형 메서드 (원본 배열을 직접 수정함)

| 메서드 | 동작 | 반환값 |
|---|---|---|
| `push(값)` | 배열 끝에 요소 추가 | 변경 후 **길이** |
| `pop()` | 배열 끝 요소 제거 | **제거한 요소** |
| `unshift(값)` | 배열 앞에 요소 추가 | 변경 후 **길이** |
| `shift()` | 배열 앞 요소 제거 | **제거한 요소** |

```js
const food = ['짜장면', '짬뽕', '볶음밥'];

const count = food.push('탕수육'); // food: [...,'탕수육'], count: 4
const removed = food.pop();        // food에서 '탕수육' 제거, removed: '탕수육'

food.unshift('유산슬'); // 맨 앞에 추가
food.shift();           // 맨 앞 요소 제거
```

> ⚠️ 위 4개 메서드는 **원본 배열을 직접 변경(mutate)** 한다는 공통점이 있음. 나중에 `filter`/`map`이 원본을 건드리지 않는 것과 대비해서 기억하기.

## 3. 값 찾기 / 존재 확인

```js
const foodList = ['물회', '삼계탕', '냉면', '수박', '물회'];

foodList.indexOf('물회');   // 0 → 처음 나오는 인덱스
foodList.indexOf('삼겹살'); // -1 → 존재하지 않을 때

foodList.includes('냉면');  // true
foodList.includes('삼겹살'); // false
```

- `indexOf`: 값의 **위치(인덱스)** 가 필요할 때
- `includes`: 값의 **존재 여부(boolean)** 만 필요할 때

## 4. 순회·변형 메서드 (콜백 기반, 원본 배열 영향 없음)

### `forEach` — 그냥 반복만, 반환값 없음
```js
students.forEach(student => {
  console.log(student.name);
});
```
- 콜백에 `(현재요소, 현재인덱스)` 순서로 전달됨
- 콜백의 반환값을 모아주지 않음 → `forEach` 자체의 반환값은 항상 `undefined`

### `map` — 요소를 변형해서 새 배열 생성
```js
const studentNames = students.map(student => student.name);
```
- 각 요소를 콜백 반환값으로 **1:1 매핑**한 새 배열 생성
- 원본 배열(`students`)엔 영향 없음

### `filter` — 조건 통과한 것만 모아 새 배열
```js
const canSell = products.filter(product => product.stock > 0);
```
- 콜백이 `true`를 반환한 요소만 모음

### `find` — 조건 통과하는 **첫 번째 요소 하나**
```js
products.find(product => product.name === '펜');
```
- 못 찾으면 `undefined` 반환 → 이어서 `.price` 등을 바로 꺼내면 에러날 수 있으니 `?.` 방어 고려

### `some` / `every` — 조건 검사 후 boolean 반환
```js
products.some(product => product.stock <= 0);  // 하나라도 만족하면 true
products.every(product => product.price > 0);  // 전부 만족해야 true
```

> **정리**: `forEach`(그냥 반복) / `map`(변형) / `filter`(선별) / `find`(단건 검색) / `some`·`every`(조건 판정) — 다섯 개 용도 구분이 핵심.

## 5. `sort()` 정렬

### 기본 동작: 콜백 없이 호출하면 **문자열 기준 오름차순**
```js
[3, 1, 9, 10, 5].sort();
// ['1', '10', '3', '5', '9'] 처럼 문자열로 변환해 앞자리부터 비교
// → 숫자 크기가 아니라 사전순으로 정렬돼서 직관과 다르게 나옴
```
- 앞에서부터 한 글자씩 비교하다가 **다른 글자가 처음 나오는 지점**에서 승부가 남 (무조건 첫 글자만 보는 게 아님)

### 숫자답게 정렬하려면 비교 콜백 필수
```js
numbers.sort((a, b) => a - b); // 오름차순
numbers.sort((a, b) => b - a); // 내림차순
```
- 콜백 반환값 **음수** → a를 b보다 앞에
- 콜백 반환값 **양수** → a를 b보다 뒤에
- 콜백 반환값 **0** → 순서 유지 (동일 순위)
- 콜백을 넣는 순간 `sort()`는 문자열 변환을 하지 않고, **콜백이 주는 숫자만으로** 순서를 정함

### 객체 배열 정렬 시 주의
```js
// ❌ 객체끼리 빼면 NaN → 정렬 안 됨
canSell.sort((a, b) => a - b);

// ✅ 비교할 필드를 명시해야 함
canSell.sort((a, b) => a.price - b.price);
```
- `price`가 원래 number 타입이면 `Number()`로 감쌀 필요 없음 (이미 숫자라 변환할 게 없음). `Number()`가 실제로 의미 있어지는 건 값이 문자열일 때, 특히 `+` 연산(문자열 이어붙기 방지)에서.

### `sort()`는 원본 배열을 직접 변경(mutate)함
```js
const sorted = numbers.sort((a, b) => a - b);
// numbers와 sorted는 같은 배열을 가리킴
```

## 6. `reduce()` — 누적값 계산

```js
const amounts = [1000, 2000, 3000];
const total = amounts.reduce((sum, current) => {
  return sum + current;
}, 0);
```
- `sum`: 누적값 (콜백 안에서만 유효한 지역변수 — 바깥에서 `console.log(sum)` 하면 에러)
- `current`: 현재 순회 중인 요소
- 두 번째 인자 `0`: 초기값

### 암묵적 리턴 축약
표현식이 하나뿐이면 `{}`와 `return` 둘 다 생략 가능:
```js
const total = amounts.reduce((sum, current) => sum + current, 0);
```

## 7. 화살표 함수 문법 정리

```js
// 매개변수 1개 → 소괄호 생략 가능
const square = x => x * x;

// 매개변수 0개 → 소괄호 생략 불가
const greet = () => '안녕하세요';

const add = (a, b) => a + b;
```

- **중괄호 본문**: `return`을 꼭 명시해야 반환됨 (일반 `function`과 동일한 규칙)
- **중괄호 생략(표현식 본문)**: 표현식 하나의 결과가 자동으로 반환됨 (`return` 생략 가능) — 이건 화살표 함수만의 전용 문법이며, 일반 `function`에는 없음
- **객체를 반환할 때**: 소괄호로 감싸야 함
  ```js
  const createUser = (id, name) => ({ id: id, name: name });
  ```
  → `{`만 있으면 JS가 "함수 블록 시작"으로 오해해서 객체가 아니라 레이블 문법으로 파싱해버림. `()`로 감싸서 "이건 표현식(객체)이다"라고 명시해주는 것.

> 💡 **생성자 함수와의 차이**: `createUser`는 `new` 없이 호출하는 **팩토리 함수**. `new`로 호출하는 생성자 함수(`function User() { this.xxx = ... }`)와는 다른 개념이며, 화살표 함수는 자기만의 `this`가 없어서 애초에 생성자로 쓸 수 없음.

## 8. 비교 연산자: `===`/`!==` vs `==`/`!=`

```js
'' == 0        // true  (타입 다른데도 변환해서 비교 — 예측 어려움)
'' === 0       // false (타입 다르면 바로 false)
```
- `==`/`!=`는 타입이 다르면 암묵적으로 변환한 뒤 비교 → 직관과 어긋나는 결과가 종종 나옴
- `===`/`!==`는 타입까지 같아야 비교 성립 → 예측 가능, 버그 적음
- **기본은 삼중 비교(`===`/`!==`)를 쓰는 습관**을 들이기

## 9. 문자열 메서드

```js
'  hello  '.trim();        // 앞뒤 공백 제거
'HELLO'.toLowerCase();     // 소문자로
'hello'.toUpperCase();     // 대문자로

'my-profile.jpg'.indexOf('profile'); // 검색어 시작 인덱스, 없으면 -1
'my-profile.jpg'.includes('.jpg');   // true/false

const fileName = 'my-profile.jpg';
fileName.slice(0, 10); // 시작 인덱스 ~ "끝 인덱스 전"까지 잘라내기

fileName.lastIndexOf('.'); // 마지막 마침표(.)의 인덱스
```

### `split` — 문자열을 배열로 분리
```js
const tags = '#자바스크립트#개발자#프론트엔드';
const tagParts = tags.split('#');
console.log(tagParts); // ['', '자바스크립트', '개발자', '프론트엔드']
```

### `filter`로 빈 값 제외 (빈 문자열 조건엔 `!==` 사용)
```js
const tagList = tagParts.filter(tag => tag !== '');
```
- `!=`도 이 케이스에선 우연히 같은 결과가 나올 수 있지만, 배열 안에 숫자·null 등 다른 타입이 섞이면 결과가 달라질 수 있어 `!==`가 안전

### 메서드 체이닝
```js
const tagList2 = tags
  .split('#')
  .filter(tag => tag !== '');
```

## 10. `Math` 객체

```js
Math.round(3.6); // 4  (반올림)
Math.floor(3.6); // 3  (내림: 주어진 수보다 크지 않은 정수 중 가장 큰 값)
Math.ceil(3.1);  // 4  (올림: 주어진 수보다 작지 않은 정수 중 가장 작은 값)
```

### `Math.random()` — 0 이상 **1 미만**의 실수 반환
```js
const randomValue = Math.random(); // 0.xxxx ~ 0.9999...  (1은 절대 포함 안 됨)

const zeroToNine = Math.floor(randomValue * 10); // 0~9 정수
const oneToTen = zeroToNine + 1;                 // 1~10 무작위
```
- 난수 개수를 늘리려면 그 개수만큼 곱하면 됨 (예: 10개 필요하면 `* 10`)

### 배열에서 무작위 요소 뽑기
```js
const menus = ['비빔밥', '우동', '김밥'];
const menuIndex = Math.floor(Math.random() * menus.length);
console.log(menus[menuIndex]);
```

**동작 원리 (곱셈과 floor의 역할 구분)**
1. `Math.random()`: 0 ~ 0.9999... 사이 실수
2. `× menus.length(3)`: 범위를 0 ~ 2.9999... 로 **넓히기만** 함 (아직 정수 아님) — `Math.random()`의 최댓값이 절대 1.0이 아니므로 3을 곱해도 최댓값은 절대 3.0에 도달하지 않고 2.9999...에서 그침
3. `Math.floor(...)`: 소수점을 잘라내서 0~2.999...를 **정수 3칸(0, 1, 2)** 으로 나눔

→ 배열 길이를 곱하는 이유: 랜덤값의 범위를 그 배열의 유효 인덱스 범위(0 ~ length-1)에 딱 맞추기 위함.
