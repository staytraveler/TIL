## 1. `&&` 단축 평가와 그 한계

`&&`는 boolean을 반환하는 연산자가 아니라, **피연산자 중 하나의 값을 그대로 반환**하는 연산자다.

```javascript
const A = false or falsy 값;
A && B
// A가 falsy면 → A값을 그대로 반환 (B는 평가조차 안 함)
// A가 truthy면 → B를 평가해서 반환
```

**문제 상황**: 빈 문자열(`''`)처럼 falsy한 값을 판별에 쓰면 원하는 값이 안 담긴다.

```javascript
const str = '';
const len = str && str.length; // len에는 str.length(0)가 아니라 str('') 자체가 담김
```

**주의**: `Boolean(A && B)`처럼 전체를 `Boolean()`으로 감싸면 항상 `Boolean(A) && Boolean(B)`와 같은 결과가 나온다 (수학적으로 동치). 다만 이건 "boolean 판단용"일 때만 의미 있고, `len`처럼 **실제 값**을 담고 싶은 목적에는 맞지 않는다.

**`if`/`for` 조건절에서도 `&&`는 똑같이 동작한다.** boolean으로 바뀌는 게 아니라, `&&`가 반환한 값을 `if`/`for`가 넘겨받아 **자체적으로** truthy/falsy 판단만 하는 것.

**자바와의 차이**: 자바의 `&&`는 피연산자·반환값 모두 `boolean`만 가능(정적 타입). JS의 `&&`는 아무 타입이나 받고 그 타입 그대로 반환한다(동적 타입) → "논리연산자"라기보다 "값을 골라주는 연산자"에 가까움.

## 2. 옵셔널 체이닝 (`?.`)

좌항이 `null`/`undefined`면 에러 없이 `undefined`를 반환하고, 아니면 우항 프로퍼티 참조를 이어간다.

```javascript
const obj = null;
const val = obj?.value; // undefined (에러 안 남)

const str = '';
const len = str?.length; // 0 (기존 && 방식의 falsy 함정 없음)
```

**실무에서 매우 자주 쓰임**: API 응답, 중첩 객체, 함수 존재 여부 확인(`callback?.()`), 배열 접근(`arr?.[0]`) 등 "값이 있을지 확신 못 하는" 모든 상황.

---

## 3. null 병합 연산자 (`??`)

좌항이 **정확히 `null` 또는 `undefined`일 때만** 우항(기본값)을 반환. 그 외 falsy값(`0`, `''`, `false`)은 그대로 유지.

```javascript
const value = '' ?? '기본 값'; // '' (빈 문자열 그대로 유지됨, || 였다면 '기본 값'으로 덮어써짐)
```

**`||`의 문제점**: falsy 전부를 "값 없음"으로 취급 → 의도적으로 넣은 `0`, `false` 같은 유효한 값까지 기본값으로 덮어씀.

**`?.` + `??` 조합**이 실무에서 세트로 자주 쓰임:
```javascript
const city = user?.address?.city ?? '주소 미입력';
```

## 4. `'use strict'` (엄격 모드)

느슨했던 JS 동작을 명시적 에러로 바꿔주는 선언.
- 선언 없이 변수 할당 → `ReferenceError`
- 함수 내부 `this`가 `undefined`(비엄격 모드는 전역 객체)
- 중복 매개변수 이름 금지 등

`class`, 모듈(`import`/`export`) 문법은 자동으로 엄격 모드 적용됨.

## 5. 프로토타입(prototype)

### 5-1. `Object.create(대상)`
괄호 안에 넣은 객체가 **프로토타입**이 되고, 그 결과가 새 객체다.
```javascript
const student = Object.create(user); // student의 프로토타입이 user
```
`student`에 없는 프로퍼티를 찾으면 프로토타입 체인을 타고 `user`까지 올라가서 찾는다.

### 5-2. `this`는 "누가 호출했는지"로 결정된다
메서드가 어디서 정의됐는지가 아니라, **호출 시 점(`.`) 앞의 객체**가 `this`가 된다.
```javascript
const user = { id: 'user', login() { console.log(`${this.id}님이 로그인`); } };
const student = Object.create(user);
student.id = 'student';
student.login(); // "student님이 로그인" — login 함수는 user 것을 빌려썼지만 this는 호출 주체
```
→ 함수 코드는 하나뿐이지만, `this`가 동적으로 바뀌므로 여러 객체가 "자기 것처럼" 재사용 가능.

### 5-3. 두 가지 탐색은 별개다
1. **메서드 자체를 찾는 것** (프로토타입 체인을 타고 올라감)
2. **그 메서드 안 `this.프로퍼티`를 찾는 것** (호출 주체 자신부터 다시 새로 탐색 시작)

```javascript
const greedyStudent = Object.create(student);
greedyStudent.id = 'student01';
greedyStudent.login();
// 1) login 함수 찾기: greedyStudent(없음)→student(없음)→user(있음, 여기서 실행)
// 2) this.id 찾기: this는 greedyStudent → greedyStudent 자신이 id 가지고 있음 → 'student01'
```

### 5-4. `hasOwn`, `in`, `delete`
```javascript
Object.hasOwn(student, 'activate');  // false — 직접 소유는 아님(프로토타입에서 물려받음)
'activate' in student;                // true — 있긴 있음(직접이든 상속이든)
delete greedyStudent.id;              // 자기 소유의 id만 지움(프로토타입 값은 안 건드림)
// 지운 뒤 조회하면 다시 체인을 타고 올라가 상위(user)의 값이 드러남
```

### 5-5. 생성자 함수 + prototype (실전 패턴)
```javascript
function Book(title, price) {
    this.title = title;   // 데이터: 인스턴스마다 다르니 생성자 안에
    this.price = price;
}
Book.prototype.getTotal = function (quantity) {  // 메서드: 다 똑같은 로직이니 prototype에 하나만
    return this.price * quantity;
};
```
- 생성자 함수 안(`this.xxx = ...`)에 메서드를 넣으면 `new`할 때마다 **함수가 매번 새로 생성**됨 → 메모리 낭비, `book1.getTotal === book2.getTotal`이 `false`가 되어버림
- `prototype`에 두면 모든 인스턴스가 **같은 함수 하나를 공유** → `true`
- ES6 `class` 문법은 이 패턴을 문법적으로 감싼 것(메서드를 class body에 쓰면 자동으로 prototype에 붙음)

**함수 자체 비교 vs 실행 결과 비교** (헷갈리기 쉬운 포인트)
```javascript
book1.getTotal === book2.getTotal        // 함수 자체 비교 (같은 함수 공유하는지) → true
book1.getTotal(2) === book2.getTotal(2)  // 실행 결과(숫자) 비교 → 우연히 같은지, 다른 개념
```

### 5-6. prototype에 "나중에" 추가하면? (생성 시점 vs 참조)
```javascript
function Student(name, age) { this.name = name; this.age = age; }
const student1 = new Student('판다', 8);   // 이 시점엔 getInfo 없음

Student.prototype.getInfo = function () { ... }; // 나중에 추가

student1.getInfo(); // 정상 작동! ← 인스턴스는 프로토타입 "내용"을 복사해오는 게 아니라
                      //   prototype "객체 자체"를 계속 참조하기 때문에 실시간 반영됨
```

**반대로 생성자 함수 본문에 나중에 코드를 추가하면?**
```javascript
function Student(name, age) {
    this.name = name;
    this.age = age;
    this.gender = '미정'; // 나중에 추가한 줄
}
```
→ 이 코드는 **`new` 호출되는 순간에만 실행**되므로, 추가하기 **이전에 이미 만들어진 인스턴스에는 절대 소급 적용 안 됨**. 그 이후에 새로 `new`한 인스턴스만 적용받음.

| 추가 위치 | 이미 만든 인스턴스에 적용? | 이유 |
|---|---|---|
| `prototype` | ✅ 됨 | 다들 그 객체를 실시간으로 계속 참조 |
| 생성자 함수 본문 | ❌ 안 됨 | 본문은 `new` 시점에 1회 실행되고 끝 |

### 5-7. `new.target`
```javascript
function Dog(name, age) {
    if (!new.target) {          // new 없이 호출됐으면 undefined
        return new Dog(name, age); // 스스로 바로잡아 재호출
    }
    this.name = name;
    this.age = age;
}
```
`new` 없이 실수로 호출해도 안전하게 동작하도록 막아주는 방어 코드. (`class` 문법은 애초에 `new` 없이 호출하면 강제로 에러남)

## 오늘의 핵심 한 줄 정리
> **데이터(값)는 생성자 함수 안에, 메서드(공용 로직)는 prototype에 둔다.**
> prototype은 "실시간으로 공유되는 참조"이기 때문에, 나중에 기능을 추가/수정해도 기존 인스턴스까지 일괄 적용된다는 게 실무적으로 중요한 이유다.
