10/8 TIL — Java 메모리, 배열, 정렬, 클래스
1. Stack과 Heap
Java에서 객체가 메모리에 저장되는 구조를 이해하기 위해 Stack과 Heap을 구분할 수 있다.
Stack
- 메소드 호출 시 생성되는 영역
- 지역 변수, 매개변수, 참조 변수 등이 저장됨
- 메소드가 종료되면 해당 영역이 정리됨
Heap
- new로 생성한 객체와 배열이 저장되는 영역
- 더 이상 참조되지 않는 객체는 Garbage Collector가 정리
Member member = new Member();

- member → 참조 변수
- new Member() → Heap에 생성된 객체
- member가 객체를 가리킴
참조 변수와 객체는 별개이다.

2. 향상된 for문
배열이나 컬렉션의 값을 순서대로 꺼내서 사용할 때 편리하다.
for (int num : arr) {
    System.out.println(num);
}

인덱스를 직접 사용할 필요가 없기 때문에 값을 읽거나 순회할 때 적합하다.
for (int i = 0; i < arr.length; i++) {
    arr[i] *= 2;
}

인덱스가 필요하거나 배열의 요소 자체를 수정해야 한다면 일반 for문을 사용하는 것이 적합하다.
향상된 for문이 수정 자체가 불가능한 것은 아니다.
기본 자료형 값을 변수에 복사해서 받기 때문에 num을 수정해도 원본 배열은 바뀌지 않는다.

3. Arrays.toString()

java.util.Arrays를 import해야 한다.
4. 정렬
선택 정렬
현재 위치에 들어갈 가장 작은 값을 찾아 앞으로 보내는 방식.
[5, 3, 4, 1, 2]

→ 가장 작은 1을 찾아 앞으로

[1, 3, 4, 5, 2]

핵심: 최솟값을 찾아 앞에 배치
버블 정렬
서로 붙어 있는 값을 비교해서 큰 값을 뒤쪽으로 보내는 방식.
[5, 3, 4, 1]

5와 3 비교 → [3, 5, 4, 1]
5와 4 비교 → [3, 4, 5, 1]
5와 1 비교 → [3, 4, 1, 5]

핵심: 인접한 값을 비교해서 큰 값을 뒤로 이동
Arrays.sort()
Java에서 배열을 정렬할 때 사용하는 메소드.
Arrays.sort(arr);

선택 정렬이나 버블 정렬 중 하나를 단순히 골라 사용하는 것이 아니라, Java가 자료형 등에 맞는 정렬 알고리즘을 내부적으로 사용한다.
실무에서는 직접 정렬 알고리즘을 구현하기보다 Arrays.sort()를 사용하는 경우가 일반적이다.

5. 클래스와 객체
클래스
객체를 만들기 위한 설계도 또는 정의.
public class Member {
    private String id;
    private String name;
}

Member라는 객체가 어떤 데이터와 기능을 가질지 정의한다.
필드
클래스 내부에 선언된 변수.
private String id;
private String name;

객체가 가지는 데이터 또는 상태를 나타낸다.
객체 생성
Member member = new Member();

- Member → 자료형
- member → 참조 변수
- new Member() → 실제 객체 생성
객체 생성 흐름
클래스 정의
   ↓
new로 객체 생성
   ↓
참조변수로 객체를 가리킴

6. 접근 제한자
클래스나 필드, 메소드 등에 어디까지 접근할 수 있는지 제한한다.
제한자	접근 범위
public	어디서든
protected	같은 패키지 + 다른 패키지의 자식 클래스
default	같은 패키지
private	해당 클래스 내부


특히 필드는 일반적으로 private으로 숨기고 Getter/Setter 등을 통해 접근하도록 만든다.
7. Getter / Setter와 캡슐화
Getter
필드의 값을 외부에 반환한다.
public String getName() {
    return name;
}

Setter
외부에서 전달받은 값으로 필드를 변경한다.
public void setName(String name) {
    this.name = name;
}

boolean 타입은 Getter 이름을 보통 isXXX() 형태로 작성한다.
public boolean isActivated() {
    return activated;
}

캡슐화
객체의 내부 데이터를 private 등으로 숨기고 외부에서는 정해진 메소드를 통해 접근하도록 하는 것.
단순히 Getter/Setter를 만드는 것이 캡슐화의 전부는 아니다.
public void setAge(int age) {
    if (age >= 0) {
        this.age = age;
    }
}

이처럼 Setter에서 유효성 검사를 하여 객체의 상태를 보호할 수도 있다.
내부 데이터를 숨기고 필요한 방식으로만 접근하게 하는 것 = 캡슐화

8. 추상화
복잡한 내부 구현은 숨기고 사용자에게 필요한 기능만 보여주는 것.
예를 들어:
member.login();

사용자는 login()이라는 기능만 사용하면 되고, 내부에서 DB를 조회하거나 비밀번호를 검사하는 과정까지 알 필요는 없다.
어떻게 동작하는지는 숨기고, 무엇을 할 수 있는지를 보여주는 것

9. DTO
Data Transfer Object
여러 데이터를 하나의 객체로 묶어서 전달하기 위한 객체.
public class MemberDTO {
    private String id;
    private String name;
    private String email;
}

회원 정보를 하나씩 따로 전달하는 대신 MemberDTO 하나에 묶어서 전달할 수 있다.
DTO = 데이터 전달을 위한 객체

10. 생성자
객체가 생성될 때 호출되어 객체의 초기 상태를 설정하는 역할을 한다.
public Member(String id, String name) {
    this.id = id;
    this.name = name;
}

생성자 규칙
1. 클래스 이름과 동일해야 함
2. 반환 타입을 작성하지 않음
3. 객체 생성 시 호출됨
Member member = new Member("user01", "홍길동");

객체 생성과 동시에 필요한 데이터를 전달할 수 있다.
기본 생성자
매개변수가 없는 생성자.
public Member() {
}

클래스에 생성자를 하나도 작성하지 않으면 Java 컴파일러가 기본 생성자를 자동으로 만들어준다.
하지만 매개변수가 있는 생성자라도 하나 작성하면 기본 생성자는 자동 생성되지 않는다.
public Member(String id) {
    this.id = id;
}

이 상태에서:
new Member();

를 사용하려면 기본 생성자를 직접 만들어줘야 한다.
