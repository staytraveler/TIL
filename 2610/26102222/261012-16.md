# 2026.10.12 TIL — 오버로딩, static/final, 싱글톤, 메모리, 계층 분리

## 1. 메서드 오버로딩(Overloading)
- 메서드 이름은 같고 **매개변수의 타입·개수·순서**가 다르면 여러 개 정의 가능
- 반환 타입만 다른 것은 오버로딩 불가

## 2. 가변인자(Varargs)
- `String... toppings` : 전달인자를 0개 이상 받음
- 메서드 내부에서는 배열처럼 사용 (`Arrays.toString(toppings)`)
- 가변인자는 일반적으로 매개변수 목록의 마지막에 작성

## 3. 값 전달과 참조형
- Java는 **항상 값에 의한 전달(Pass by Value)**
- 기본형: 값 자체가 복사됨
- 참조형: 객체를 가리키는 참조값이 복사됨
- 참조값이 가리키는 객체를 수정하면 원본 객체에도 영향이 있음
- 단, 매개변수에 다른 객체를 재할당해도 호출한 쪽의 참조 변수 자체는 바뀌지 않음

## 4. static / 인스턴스 / final
- `static` : 클래스에 속함. 객체 생성 없이 접근 가능하며 모든 인스턴스가 공유
- 인스턴스 필드: 객체마다 별도로 존재
- `static final` : 공유하는 상수. 보통 `MAX_SIZE`처럼 대문자와 `_` 사용
- `final` 인스턴스 필드: 한 번 초기화하면 재할당 불가. 생성자에서 초기화 가능
- `final` 필드는 setter로 값을 바꿀 수 없음

## 5. 싱글톤 패턴(Singleton)
특정 클래스의 인스턴스를 하나만 사용하도록 설계하는 패턴.

1. `private` 생성자: 외부의 `new` 차단
2. `private static` 필드: 유일한 객체 보관
3. `public static getInstance()` : 객체 반환

- **Eager**: 클래스 초기화 시 미리 생성
- **Lazy**: `getInstance()` 최초 호출 시 생성
- 주의: 기본 Lazy 구현은 멀티스레드 환경에서 동시 생성 문제가 발생할 수 있음

## 6. 메모리와 변수
- **Heap**: `new`로 생성한 객체가 저장되는 영역
- **Stack**: 메서드 호출에 따른 스택 프레임, 지역 변수 등이 관리되는 영역
- **Static 영역**: 클래스 변수 등 클래스 관련 데이터가 관리되는 영역
- 인스턴스 변수: 객체마다 존재
- static 변수: 클래스 단위로 공유
- 지역 변수·매개변수: 메서드 실행과 관련해 관리됨

※ 메모리 구조는 JVM 구현에 따라 세부 사항이 달라질 수 있음.

## 7. 계층 분리 (Layered Architecture)
역할별로 코드를 나누어 유지보수와 테스트를 쉽게 하는 구조.

- **Controller**: 요청을 받고 응답 반환
- **Service**: 비즈니스 로직 처리
- **Repository**: 데이터 저장·조회 담당
- **DTO**: 계층 간 데이터를 전달하는 객체
- **Entity**: 데이터베이스 테이블과 매핑되는 도메인 객체

일반적인 흐름:

`Client → Controller → Service → Repository → DB`

응답은 보통 반대 방향으로 돌아옴.

DTO는 데이터 전달용 객체라서 Controller와 Service 사이 등 필요한 경계에서 사용한다. 모든 계층에 무조건 DTO를 만들 필요는 없다.

## 핵심 기억
- 오버로딩 = 같은 이름, 다른 매개변수
- static = 클래스 공유 / 인스턴스 = 객체별 독립
- final = 재할당 불가
- 싱글톤 = 인스턴스 하나를 공유
- Repository = 데이터 접근
- 계층 분리 = 각 계층이 자기 역할만 담당


# TIL | 2026.10.13 Java 상속 · 다형성 · 추상클래스 · 인터페이스

## 1. 상속 (Inheritance)
- 부모 클래스의 공통 상태와 기능을 자식 클래스가 물려받아 재사용·확장하는 것
- `extends` : 클래스 상속 (부모 클래스는 하나만 가능)
- `super()` : 부모 생성자 호출
- `super(code, name, price)` : 매개변수가 있는 부모 생성자 호출 → 부모의 `private` 필드도 부모 생성자를 통해 초기화 가능

## 2. 오버로딩 vs 오버라이딩
- **오버로딩**: 같은 이름의 메서드를 매개변수 목록을 다르게 하여 여러 개 정의
- **오버라이딩**: 자식 클래스가 부모 메서드를 재정의
- 오버라이딩 조건: 메서드명·매개변수 목록 동일, 반환 타입은 호환되어야 함, 접근 범위는 부모와 같거나 넓어야 함
- `private` 메서드: 오버라이딩 불가 / `final` 메서드: 재정의 불가, 호출은 가능
- `protected`: 같은 패키지 및 다른 패키지의 자식 클래스 등에서 접근 가능

## 3. 다형성 (Polymorphism)
- 부모 타입 참조변수로 자식 객체를 참조할 수 있음
  ```java
  Animal animal = new Dog();
  ```
- **업캐스팅**: 자식 객체를 부모 타입으로 참조
- **동적 바인딩**: 오버라이딩된 메서드는 실행 시 실제 객체의 메서드가 호출됨
- 부모 타입에서는 부모에게 선언된 멤버만 직접 접근 가능
- 자식 고유 기능을 사용하려면 **다운캐스팅** 필요
  ```java
  if (animal instanceof Dog) {
      Dog dog = (Dog) animal;
  }
  ```
- 다운캐스팅 전 `instanceof`로 객체 타입을 확인하면 안전함
- 메서드 매개변수에도 다형성을 적용할 수 있음

## 4. 추상 클래스 (Abstract Class)
- `abstract`로 선언하며, **직접 객체를 생성할 수 없는 미완성 부모 클래스**
- 공통 필드·기능을 정의하고 자식 클래스가 확장하도록 설계
- 일반 메서드와 추상 메서드를 모두 가질 수 있음
- 추상 메서드는 몸체가 없으며, 구체적인 자식 클래스가 반드시 구현해야 함
- 참조변수 타입으로는 사용 가능 → 다형성 적용 가능

## 5. 인터페이스 (Interface)
- 클래스가 구현해야 할 기능의 규칙(계약)을 정의
- `interface`로 선언하고, 클래스는 `implements`로 구현
- 인터페이스는 직접 객체 생성 불가
- 구현 클래스는 추상 메서드를 구현해야 함
- 추상 메서드에는 기본적으로 `public abstract`가 적용됨
- 인터페이스 타입으로 구현 객체를 참조할 수 있음 → 다형성 적용 가능
- 클래스는 부모 클래스를 하나만 상속하지만, 인터페이스는 여러 개 동시 구현 가능
  ```java
  class SmartPhone implements Call, Camera, Music { }
  ```

## 핵심 비교
- **상속**: 부모의 기능을 물려받아 재사용
- **추상 클래스**: 공통 속성과 기능을 정의하는 미완성 부모 클래스
- **인터페이스**: 클래스가 지켜야 할 기능의 규칙
- **다형성**: 하나의 부모 타입으로 여러 자식 객체를 다루는 성질


# TIL | Java API, Object, String, Wrapper, 날짜/시간, 제네릭

**날짜:** 2026.10.14.

## 1. API & Object

### API
- 프로그램에서 제공하는 기능을 사용할 수 있도록 정해 놓은 인터페이스와 사용 규칙
- Java API와 Web API는 환경은 다르지만, 기능을 사용하기 위한 규약이라는 공통 개념을 가진다.

### Object
- 모든 Java 클래스의 최상위 부모 클래스이며, 클래스는 `Object`를 직접 또는 간접적으로 상속한다.
- `Object`의 공통 메서드를 사용할 수 있으며, 필요에 따라 오버라이딩한다.

| 메서드 | 설명 |
|---|---|
| `toString()` | 객체 정보를 문자열로 반환 |
| `equals()` | 객체의 동등성을 비교하도록 재정의 가능 |
| `hashCode()` | 객체의 해시 코드 반환 |

- `toString()` 기본 반환 형식: `클래스명@16진수해시값`
- 기본 `equals()`는 객체 참조를 기준으로 비교한다. 필드값이 같으면 같다고 판단하고 싶을 때 오버라이딩한다.

| 구분 | 의미 | 예시 |
|---|---|---|
| 동일성 | 같은 객체인가? | `a == b` |
| 동등성 | 객체의 내용이 같은가? | `a.equals(b)` |

※ `equals()`를 재정의하면 일반적으로 `hashCode()`도 함께 재정의해야 한다. 특히 `HashSet`, `HashMap`에서 중요하다.

## 2. String & StringBuilder

### 2-1. String

- 문자열은 **불변(Immutable) 객체**다. 문자열을 변경하는 연산은 새로운 문자열을 반환하며, 기존 문자열 자체는 바뀌지 않는다.
- 문자열 리터럴은 String Constant Pool을 활용해 동일한 문자열을 공유할 수 있다.
- `new String("Java")`는 리터럴과 별도의 문자열 객체를 생성한다. 문자열 내용까지 달라지는 것은 아니다.
- `String`은 `equals()`가 오버라이딩되어 있어 문자열 내용을 비교할 수 있다.

| 메서드 | 기능 |
|---|---|
| `trim()` | 앞뒤 공백 제거 |
| `toUpperCase()` / `toLowerCase()` | 대소문자 변환 |
| `indexOf()` | 특정 문자열의 위치 검색 |
| `substring(start, end)` | 시작 인덱스부터 끝 인덱스 직전까지 추출 |
| `replace(target, replacement)` | 문자열 치환 |
| `split(regex)` | 정규식을 기준으로 분리해 배열 반환 |
| `isEmpty()` | 문자열 길이가 0이면 `true` |
| `String.valueOf(value)` | 값을 문자열로 변환 |

**주의사항**
- 문자열은 인덱스가 `0`부터 시작한다.
- `split()`은 구분자를 정규식으로 해석한다. 마침표 `.` 등은 이스케이프가 필요할 수 있다.
- `isEmpty()`는 공백만 있는 문자열을 `true`로 판단하지 않는다.
- `null` 가능성이 있는 문자열은 `"기준값".equals(input)`으로 비교하면 `NullPointerException`을 방지할 수 있다.

### 2-2. 이스케이프 문자

문자열 안에서 특수한 기능을 표현하며, 역슬래시(`\`)로 시작한다.

| 문자 | 의미 |
|---|---|
| `\n` | 줄바꿈 |
| `\t` | 탭 |
| `\"` | 큰따옴표 |
| `\'` | 작은따옴표 |
| `\\` | 역슬래시 |

### 2-3. StringBuilder

- **가변(Mutable) 객체**로, 문자열을 반복해서 조립할 때 효율적이다.
- `String`은 불변이므로 반복적인 문자열 연결에서 불필요한 객체 생성이 발생할 수 있다.

| 메서드 | 기능 |
|---|---|
| `append(value)` | 뒤에 추가 |
| `delete(start, end)` | 시작 인덱스부터 끝 인덱스 직전까지 삭제 |
| `insert(index, value)` | 지정 위치에 삽입 |
| `reverse()` | 문자열 순서 뒤집기 |

- `append()`는 자기 자신을 반환하므로 메서드 체이닝이 가능하다.

```java
StringBuilder sb = new StringBuilder();
sb.append("Java")
  .append(" ")
  .append("Study");

System.out.println(sb); // Java Study
```

## 3. Wrapper & 형변환

### Wrapper 클래스
- 기본 자료형의 값을 객체 형태로 감싸는 클래스
- 예: `int` → `Integer`, `double` → `Double`, `boolean` → `Boolean`
- 기본 자료형을 객체가 필요한 곳에서 사용할 수 있게 한다.

### Boxing / Unboxing
- **Boxing**: 기본 자료형 → Wrapper 객체
- **Unboxing**: Wrapper 객체 → 기본 자료형
- **Auto-Boxing / Auto-Unboxing**: 컴파일러가 위 변환을 자동 처리

```java
Integer num = 10; // Auto-Boxing
int value = num;  // Auto-Unboxing
```

- Wrapper 객체는 `null`을 가질 수 있다. 단, `null`을 기본형으로 자동 언박싱하면 `NullPointerException`이 발생한다.
- Wrapper 값 비교에는 `equals()`를 사용하는 것이 안전하다. `==`는 객체 참조 비교이므로 주의한다.

### 문자열과 자료형 변환

| 메서드 | 변환 |
|---|---|
| `Integer.parseInt("123")` | `String` → `int` |
| `Double.parseDouble("3.14")` | `String` → `double` |
| `String.valueOf(123)` | 숫자 → `String` |
| `Integer.valueOf("123")` | `String` → `Integer` |

- **Parsing**: 문자열을 원하는 자료형으로 변환하는 과정
- 숫자로 변환할 수 없는 문자열을 `parseInt()` 등에 전달하면 `NumberFormatException`이 발생한다.

## 4. 날짜와 시간 (`java.time`)

### 주요 클래스

| 클래스 | 용도 |
|---|---|
| `LocalDate` | 날짜 |
| `LocalTime` | 시간 |
| `LocalDateTime` | 날짜 + 시간 |
| `ZonedDateTime` | 시간대 정보를 포함한 날짜와 시간 |
| `ZoneId` | 시간대 식별 |

- `now()` : 현재 날짜 또는 시간 조회
- `plus...()` / `minus...()` : 날짜 및 시간 계산
- 날짜·시간 객체는 불변 객체이므로 계산 결과를 다시 저장해야 한다.

### DateTimeFormatter

날짜·시간 객체와 문자열 사이의 변환에 사용한다.

**Format: 날짜·시간 객체 → String**

```java
DateTimeFormatter formatter =
    DateTimeFormatter.ofPattern("yyyy년 MM월 dd일 HH시 mm분");

String result = LocalDateTime.now().format(formatter);
```

**Parse: String → 날짜·시간 객체**

```java
String date = "20261225";

DateTimeFormatter parser =
    DateTimeFormatter.ofPattern("yyyyMMdd");

LocalDate parsedDate = LocalDate.parse(date, parser);
```

- 패턴에서 `yyyy`는 연도, `MM`은 월, `dd`는 일, `HH`는 24시간제 시, `mm`은 분, `ss`는 초를 의미한다.
- 국가별 시간대가 필요한 서비스에서는 `ZonedDateTime`과 `ZoneId`를 활용한다.

## 5. 제네릭 (Generics)

### 개념
- 클래스나 메서드에서 사용할 타입을 미리 고정하지 않고, 객체 생성이나 메서드 호출 시 지정할 수 있도록 하는 기능
- 컴파일 시 타입을 검사해 **타입 안정성**을 높이고 불필요한 형변환을 줄인다.

### 타입 매개변수

| 기호 | 일반적인 의미 |
|---|---|
| `T` | Type |
| `E` | Element |
| `K` | Key |
| `V` | Value |

※ 관례적인 이름이며 반드시 해당 문자만 사용해야 하는 것은 아니다.

### 제네릭 클래스 예시

```java
class Box<T> {
    private T value;

    public void set(T value) {
        this.value = value;
    }

    public T get() {
        return value;
    }
}

Box<String> box = new Box<>();
box.set("Java");
String value = box.get();
```

- `T`는 타입 매개변수이며, `Box<String>`에서는 `String`으로 지정된다.
- 제네릭 타입 인자에는 기본형이 아닌 참조형을 사용한다. (`int` 대신 `Integer`)

### 타입 제한

```java
class Box<T extends Rabbit> {
    private T value;
}
```

- `T extends Rabbit`: `Rabbit` 또는 `Rabbit`의 하위 타입만 허용한다.
- 클래스뿐 아니라 인터페이스를 상한으로 지정할 수도 있다.

## 핵심 암기

- `==` : 동일성 비교 / `equals()` : 동등성 비교
- `String` : 불변 / `StringBuilder` : 가변
- `String.valueOf()` : 문자열 변환 / `parseInt()` : 문자열을 `int`로 변환
- Boxing : 기본형 → 객체 / Unboxing : 객체 → 기본형
- Format : 날짜·시간 객체 → 문자열 / Parse : 문자열 → 날짜·시간 객체
- Generics : 타입 안정성 확보 및 불필요한 형변환 감소
- `T extends Rabbit` : `Rabbit` 또는 하위 타입으로 제한
